`DocxEditor` is the single component the React entry exports.
This page lists its props and the handle behind its ref; the guides linked from each row carry
the longer explanation.

## Props

| Prop | Type | Default | What it does |
| --- | --- | --- | --- |
| `document` | `ArrayBuffer \| Uint8Array \| Blob` | required | The document to open. Bytes open immediately; a `Blob` or `File` is read first, and whichever document arrived last is the one opened. |
| `mode` | `DocxEditorMode` | required | What the editor is for, and whose comments it writes. See [Mode](#mode). |
| `renderImportError` | `(error: DocxImportError) => ReactNode` | built-in panel | What to render in place of the editor when the document was refused. |
| `showPageGuides` | `boolean` | `true` | Whether to draw approximate page boundaries over the document's paper. Drawn in every mode. |
| `zoom` | `DocxEditorZoom` | uncontrolled | The visual scale, when the host owns the selection. |
| `defaultZoom` | `DocxEditorZoom` | `"fit-width"` | The initial scale when the editor owns the selection. |
| `onZoomChange` | `(zoom: DocxEditorZoom) => void` | — | Receives toolbar requests. A controlled host must update `zoom` for one to take effect. |
| `fontFallbacks` | `FontFallbacks` | `DEFAULT_FONT_FALLBACKS` | The fonts drawn in place of names missing from the reader's machine. See [Styling](/docs/styling#font-fallbacks). |
| `presets` | `DocxEditorPresets` | package defaults | The lists the built-in pickers offer. See [Custom controls](/docs/custom-controls#presets-and-plugins). |
| `plugins` | `readonly Plugin[]` | — | ProseMirror plugins placed ahead of the built-in ones, so a host keymap sees an event first. |
| `contextMenus` | `boolean` | `true` | Whether the right click opens the editor's own menus. `false` leaves the right button to the browser, which is what a host drawing menus of its own wants. |
| `className` | `string` | — | Added to the editor's outer frame alongside its own class. |
| `style` | `CSSProperties` | — | Applied to that same frame. |
| `onReady` | `(view: EditorView) => void` | — | Called with the view once the editor has mounted a document. |
| `onChange` | `() => void` | — | Called on every editor state change, which includes cursor and selection moves. |

`DocxEditorProps`, `DocxEditorMode`, `DocxEditorZoom`, `DocxEditorPresets`, `CommentAuthor`,
`EditableComments`, and `DocxSource` are all exported from the root entry, so a wrapper component
can name them without restating their shapes.

## Mode

`mode` is a union of three kinds: a reader's surface, a commenter's, and an editor's.
Whether the right button opens the editor's own menus is the `contextMenus` prop rather than part
of a kind, because the plugins behind it are read when the editor mounts.

```ts
type DocxEditorMode =
  | { kind: "readOnly" }
  | {
      kind: "comment";
      author: CommentAuthor;
      editableComments?: EditableComments;
    }
  | {
      kind: "edit";
      author: CommentAuthor;
      editableComments?: EditableComments;
      toolbar?: boolean;
      locking?: boolean;
    };

interface CommentAuthor {
  id: string;
  name: string;
  initials?: string;
}

type EditableComments = "own" | "all";
```

`readOnly` takes no edits and no comments.
`comment` lets the text be selected and copied but not changed, while comments may be written,
answered, resolved, and reopened.
`edit` takes everything.
[Modes and protection](/docs/custom-controls#modes-and-protection) explains what each kind enforces
and how a custom control reads it.

`author` is the identity the built-in comment and reply composers write.
`id` is an opaque string the host application chooses, such as its own user id, and is recorded in
the document beside the display name; `name` is what the comment shows; `initials` is the short
form Word uses where a name does not fit, and is optional.

Within one file a display name stands for one identity, so give each `id` a distinct `name`; a
name two ids share, or one a Word user recorded first, resolves to no identity and its comments
become everyone's to edit.

`editableComments` is whose comments the panel offers to edit or delete.
`"own"`, the default, is a comment carrying this `id` or no recorded identity at all; `"all"` is
every comment.
Replying, resolving, and reopening are open to every commenter either way.

`toolbar` defaults to `true`.
`locking` defaults to `false` and adds the controls for settling part of a document; a lock the
document already carries is honored in every mode.
See [Locked content](/docs/custom-controls#locked-content) for the commands behind it.

The kind, `author`, and `editableComments` may change on an open document: the editor switches
in place and keeps the view, its history, and the host's plugins.

## The handle

```ts
interface DocxEditorHandle {
  view: EditorView;
  exportBytes: () => Uint8Array;
}
```

The ref holds `null` until a document has been opened, and holds `null` again for a document that
was refused, so a control that exports should read it at click time rather than caching it.
`exportBytes` writes the state currently on screen and throws `DocxExportError` when it cannot do
so safely.
[Getting started](/docs/getting-started#export-the-edited-document) covers `downloadDocx`, which
wraps the handle for the ordinary browser download.

## Props read once

Most props take effect on the render that changes them, `mode` included.
Four values are read when the editor mounts, because they go into the ProseMirror state and the
view built around it:

- `plugins`
- `fontFallbacks`
- `defaultZoom`
- `contextMenus`

Building any of them inline on every render is therefore harmless.
To change one, change the component's `key` and let it remount, which is also how the component
asks for a document to be swapped.

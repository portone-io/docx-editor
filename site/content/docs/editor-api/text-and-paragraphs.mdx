Everything on this page comes from `@portone/docx-editor/commands` and follows the contract
described in [Commands and queries](/docs/editor-api#commands-and-queries).

## Character formatting

| Command | Query | What it does |
| --- | --- | --- |
| `toggleBold` | `isBoldActive` | Turns bold on or off. |
| `toggleItalic` | `isItalicActive` | Turns italic on or off. |
| `toggleUnderline` | `isUnderlineActive` | Switching it on writes a single underline; a run already underlined keeps the kind it has. |
| `toggleStrike` | `isStrikeActive` | Turns strikethrough on or off. |
| `setTextColor(hex)` | `activeTextColor` | Writes the color as `#RRGGBB`. Null withdraws it. |
| `setTextBackground(hex)` | `activeTextBackground` | Writes the background as `#RRGGBB`. Null withdraws it, and a `w:highlight` an older document wrote at that spot goes with it. |

`RunToggle` names the four toggles as a union, for a control that keeps them in a list.

`canFormatText` is the gate the whole group is drawn from. A selection running over a lock keeps
its say, because the locked pieces are left out rather than the whole edit refused; only a
selection the lock leaves nothing of has nothing to format. A caret formats no text of its own, so
what settles it there is whether the text typed next could go in at all.

## Fonts

| Command | Query | What it does |
| --- | --- | --- |
| `setFontFamily(name)` | `activeFontFamily(state, fontFallbacks?)` | Sets the font by name. Null withdraws the setting and falls back to the document default. |
| `setFontSize(pt)` | `activeFontSize(state)` | Sets the size in points. Null withdraws the setting and falls back to the document default. |

Both readers answer with a kind rather than a bare value, because a picker has three states to
draw and not two.
`kind: "font"` and `kind: "size"` are a value every selected character shares, one a paragraph
style gives included.
`kind: "default"` means nobody wrote a value down, and `name` or `pt` is what is actually
rendered: the document's own default where it has one, and the on-screen fallback where it has
none.
`kind: "mixed"` means the selection holds several.

Pass `activeFontFamily` the same `FontFallbacks` the editor was given, so the name it reports for
an unspecified font is the one on screen. The root entry exports `DEFAULT_FONT_FALLBACKS`.

`documentDefaults(state)` returns the document's own `fontFamily`, `fontSizePt`, and `lineSpacing`,
each null where the document wrote none.
`documentFontNames(doc, defaults)` returns every font name the document uses. It walks the whole
document, so call it when the document changes rather than on every render; the built-in font
picker appends its result after the preset list.

## Paragraphs

| Command | Query | Gate |
| --- | --- | --- |
| `setParagraphStyle(styleId)` | `activeParagraphStyle` | |
| `setParagraphAlign(align)` | `activeParagraphAlign` | `canSetParagraphAlign` |
| `setLineSpacing(spacing)` | `activeLineSpacing` | `canSetLineSpacing` |
| `increaseIndent`, `decreaseIndent` | | `canIncreaseIndent`, `canDecreaseIndent` |

`documentParagraphStyles(state)` returns the styles the document defines as `ParagraphStyleOption`
records: `id`, the display `name`, `isDefault` for the one a paragraph with no style already wears,
`primary` for a style meant for a prominent gallery, and `hidden` for one Word keeps out of its
own. `setParagraphStyle(null)` puts a paragraph back on the default style. Applying a style writes
nothing but the style reference, the same as Word, so direct formatting already written keeps
beating it.

`activeParagraphStyle` answers `{ kind: "shared", styleId }` when the selected paragraphs all point
at one style, with a null id meaning the default style, `{ kind: "mixed" }` when they point at
several, and `{ kind: "none" }` when the selection holds no paragraph at all.
`activeParagraphAlign` answers `{ kind: "shared", align }` or `{ kind: "mixed" }`; a selection
holding no paragraph is mixed as well. Exactly one alignment is always on, so there is no command
to clear one.

`LineSpacing` is one of `{ rule: "auto", lines }`, `{ rule: "exact", pt }`, or
`{ rule: "atLeast", pt }`, and `SINGLE_LINE_SPACING` is the one line a paragraph nobody spaced is
drawn with. `activeLineSpacing` returns null when the selection mixes several.

The indent commands move an ordinary paragraph's own left indent by half an inch, Word's step. In a
list paragraph they move the item one level instead, which is what Tab and Shift+Tab do there. A
selection holding both kinds gets each paragraph treated by its own rule.

## Lists

| Command | Query | What it does |
| --- | --- | --- |
| `toggleNumberedList` | `activeListKind` | Starts a numbered list, or takes the paragraphs out of one. |
| `toggleBulletList` | `activeListKind` | Starts a bulleted list, or takes the paragraphs out of one. |
| `increaseListLevel` | `isInList` | Moves a list item one level deeper. |
| `decreaseListLevel` | `isInList` | Moves a list item one level back up. |

`activeListKind` returns `"numbered"`, `"bullet"`, or null. Paragraphs turned into a list together
share one numbering id, so they become a single continuous list.

Starting a list records its definition on the document in the same transaction, and export writes
that definition into numbering.xml. A definition needs a numbering part to go into, whether the
document arrived with one or export writes it; where the package has no content types part to
declare a new one, the list commands report that they do not apply rather than allowing an edit
that export would refuse. [Checking before
export](/docs/core/errors#checking-before-export) covers that code.

## Breaks and tabs

`insertLineBreak` breaks the line without splitting the paragraph, and `insertPageBreak` starts the
next page. Both are the same breaks the keyboard binds to Shift+Enter and Mod+Enter, and both go in
in place of whatever is selected, so each reports that it does not apply where a lock, a preserved
marker, or the mode shuts that spot.

Use `insertTab` to insert the same editable DOCX tab as the built-in Tab binding. It applies inside
an ordinary paragraph; table cells and list paragraphs keep their navigation and level-changing Tab
behavior.

## History

`undo` and `redo` are the editor's own rather than prosemirror-history's. They find the history
this editor keeps, which a consumer's own copy of prosemirror-history would not, and they carry the
pass a replayed lock needs: a raw history command is refused the moment the history reaches a lock,
and that refusal puts everything behind it out of reach.

Both are ordinary commands, so calling one without a dispatch is how a button knows whether there
is anything to take back. Under the `comment` mode they take a comment back but not a body edit,
from the keyboard as well as from the panel, and under `readOnly` a reader has nothing to undo.

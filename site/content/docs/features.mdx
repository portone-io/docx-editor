title: Features
description: What the editor edits, what it preserves untouched, and its current limitations.

`@portone/docx-editor` edits common DOCX body content while preserving document structures
outside its editing surface.

This page is the user-facing support summary. API details live in
[Custom controls](/docs/custom-controls) and [Core API](/docs/core).

## Supported features

| Area | What you can do |
| --- | --- |
| Text formatting | Edit bold, italic, strikethrough, underline, palette or custom HEX colors, highlight, fonts, and font size. Supported document defaults and paragraph or character styles are reflected in the text and formatting controls. |
| Paragraphs | Apply paragraph styles, alignment, indentation, line spacing, line breaks, and page breaks. A paragraph marked keep with next, by itself or by its style, is shown on the same page as the start of the block after it. |
| Tabs | Insert, paste, format, navigate, select, and align document tabs using the document's automatic interval and effective paragraph stops. |
| Lists | Create and edit common bullet and numbered lists, including nested levels. A list is drawn the way its own definition asks: the format its numbers are counted in, where its counting starts over, what stands between a number and the text, and the character formatting the level puts on the number itself. A list that takes its numbers from a numbering style is drawn like any other. |
| Tables | Insert and remove rows, columns, and tables; merge, split, resize columns and rows, format, vertically align, and pad cells. A table style is displayed, its header row, closing row, edge columns, corners, and banded rows included. Long tables continue at safe row boundaries, repeating leading `tblHeader` rows. A new table is as wide as one line of body text on the paper of the section it goes into. |
| Images | Insert, paste, drop, select, and resize inline images. |
| Hyperlinks | Create, change, remove, and open external links. A link made on text inside a content control is written inside that control. |
| Comments | View anchored threads; create, edit, reply to, resolve, reopen, and delete comments. A comment body keeps its formatting through an edit: the built-in composer writes plain text, `setCommentBody` writes a formatted body, and whatever an edit does not touch goes back out as it came. Each comment records its author, so editing and deleting stay with them. Resolving a thread hides its highlight; reopening puts it back. Deleting commented text never deletes the comment: trimming keeps it on the remaining text, and deleting all of it lists it under All comments as *Original content deleted*. Word has no such state, so the saved file holds it as an ordinary comment where the deleted text was. |
| Footnotes and endnotes | View references and note bodies while editing surrounding text; a body is read the way the document body is, though editing one is not offered yet. A reference is preserved rather than edited: a selection running across one cannot be replaced, so typing or deleting over it leaves the text as it stands, and the picture, line break and page break controls are unavailable while it is held. |
| Headers and footers | Visually preview each section's plain-text first, even, and default stories, including decimal `PAGE` and `NUMPAGES` fields. A header or footer body is read the way the document body is, though editing one is not offered yet. |
| Content controls | Edit or lock supported text and table-cell controls. A control standing inside another control or inside a hyperlink, at any depth, is editable text like any other, and goes back out nested as it came. |
| Clipboard | Copy and paste inside the same document keeps paragraph and character formatting, tabs, breaks, images, links, and tables; copying a grid of cells and pasting it over selected cells fills them in place. Comment markers, bookmarks, and note references are not copied, so pasting cut content back leaves them out; cutting commented text leaves the comment behind the way deleting it does, as the Comments row describes. Copied content carries formatting but no document internals: what lands in another application has the text on the page, its styles, tables, images, and links, and none of the original XML, comment authorship, or note bodies. Pasting from another document or application keeps supported character formatting, paragraphs, destination-matched heading styles, line breaks, links, tables, and common lists, including the lists Word writes as plain paragraphs. Pasted text fills every selected table cell. Right-click Paste also accepts formatted text and images; plain-text paste ignores accompanying formatting and images. Unreadable content uses any available text fallback, or leaves the selection intact when there is nothing to insert. |
| Editor | Use built-in controls, selectable document zoom, undo and redo, keyboard navigation, and IME composition, in a read-only, comment-only, or editing mode. |

## Keyboard shortcuts

`Mod` is Command on macOS and Control elsewhere.

| Keys | What happens |
| --- | --- |
| `Enter` | Splits the paragraph, and the new paragraph keeps the original's formatting, as Word does. In an empty list item it leaves the list instead. |
| `Shift+Enter` | Inserts a line break. |
| `Mod+Enter` | Inserts a page break. |
| `Mod+B`, `Mod+I`, `Mod+U` | Toggles bold, italic, and underline. |
| `Mod+Shift+X` | Toggles strikethrough. |
| `Mod+Shift+V` | Pastes the clipboard's plain text, ignoring accompanying HTML and images. |
| `Mod+K` | Opens the link panel over the selection. With nothing to link it reports that it did nothing, so the browser keeps its own binding. |
| `Mod+Z` | Undo. |
| `Mod+Shift+Z`, `Mod+Y` | Redo. |
| `Tab` | Inside a table it moves to the next cell; in a list paragraph it increases the level; in an ordinary paragraph it inserts a document tab. |
| `Shift+Tab` | Moves to the previous cell, or decreases the list level. |
| `ArrowLeft`, `ArrowRight` | Moves the caret across a laid-out tab as one step. Holding `Shift` extends the selection instead. |
| `Escape` | Closes an open panel, menu, or link card and hands focus back to the paper. It also hides tooltips until the pointer or focus moves. |

Keys not listed here fall through to ProseMirror's base keymap, which covers ordinary caret
movement, selection, and deletion.
A keymap passed through the `plugins` prop sees events first, so an application can take over a
binding such as `Mod+K` without replacing the editor.

## Preserved content

| Content | Behavior |
| --- | --- |
| Additional Word character formatting and character styles | Existing formatting that the editor does not display or edit is preserved. |
| Bookmarks | Existing bookmark ranges are preserved at their document positions, invisible and impossible to remove. A selection running across one of the markers cannot be replaced, so typing or deleting over it leaves the text as it stands, and the picture, line break and page break controls are unavailable while it is held. Move the selection clear of the marker to edit the text around it. Deleting a row or column is also unavailable when it would remove a marker carried between rows or cells. The same holds for a permission range and for the markers of a moved passage. |
| Document fields | Complex-field markers and instructions are shown as small boxes that cannot be edited or removed. Their cached result remains editable text. A simple field is one box showing its cached result and can be removed whole. The paragraph around either kind stays editable. |
| Section breaks | Every section a document is written in is read: its paper and margins, which its own page boundaries and the width of a table put there follow, the header and footer stories it selects, and the page number it starts at. A paragraph carrying a section break keeps it. The paragraph cannot be joined away, since nothing puts a lost section back, and pressing Enter in it keeps the break on the last paragraph of the section instead of copying it onto both halves. |
| Tracked changes | An insertion or a deletion is shown as a small box carrying its text, and can be selected and removed whole; the passage inside it cannot be edited. A table's `w:tblGridChange` is preserved as it came. A rebuilt table is the exception in one place: the cells continuing a vertical merge are written from the cell that starts it, so properties of their own do not come along. |
| Other Word markup inside a paragraph | A symbol, a positional tab, a content control the editor could not take apart, and any other element it has no model for are shown as small boxes where they stood, and the paragraph around them stays editable. |

## Current limitations

- A list counts in decimal numbers, decimal numbers with a leading zero, upper or lower letters, upper or lower Roman numerals, Ganada, Korean digits, or the Chinese counting system. A list counting in any other format is shown with decimal numbers, and a level numbered with a picture is shown with the character written beside it instead.
- ECMA-376 Strict packages are refused. A Transitional document must declare the WordprocessingML prefix `w` on its main part's root.
- Tab leader glyphs and bar lines remain preserved in OOXML but are not drawn.
- Visual page boundaries are approximate and may differ from Word or printed output. Keep lines together and widow control are preserved but not reflected in them.
- Every page is drawn at the width of the first section's paper, since one sheet is drawn at one width. A page takes its height and its boundaries from the paper of the section its own text sits in, so a landscape section is paginated on landscape pages and drawn on the sheet's width.
- A table is fitted to the body width of its own section, and one wider than the sheet is drawn shrunk to fit it while the document keeps the width it was given. An image is fitted to the width the sheet draws, and a pasted one to the height the section it lands in leaves.
- A section break starts a new page unless it is marked continuous, which carries the section that follows on down the same page. An even-page or odd-page start is preserved and goes back out untouched, but it is drawn as an ordinary new page rather than skipping to a page of that side.
- A page number begins at the start its own section declares, but the count is not restarted at a section boundary: a later section's number carries on from the page's place in the whole document. Which header and footer a page shows - first, even, or default - is chosen from the page's place in its own section instead, so every section's own first page is drawn as a first page.
- A selection running across the last paragraph of a section cannot be deleted, even when the section break is not what you meant to remove. Move the selection clear of that paragraph's boundary to edit the text around it.
- The cached result text of a complex field can be edited, but nothing recalculates the field. A page number or a total that the document already drew stays as it was written.
- A table is shown as a placeholder when its row wrapper cannot be read or a marker follows a cell that only continues a vertical merge. Other markers between rows or cells are preserved while the table remains editable.

## Preservation

Content outside the supported editing surface is not silently discarded. Untouched package parts
and document blocks are written back from their original XML, and an element the editor has no
model for is kept where it stood: inside its run, beside the runs of its paragraph, or as a block.
A paragraph stays editable around its preserved elements, and a table stays a table around a
bookmark that spans one of its columns. Unsupported blocks remain placeholders, as do tables whose
structure cannot be modelled, including tables with a content control or a tracked change around
a whole row.

What a given document kept this way is not a guess: `documentFidelity` lists it, and `importDocx`
returns the same list for a file opened outside the editor.

If a safe round trip cannot be guaranteed, import or export fails with a stable error code instead
of returning a damaged document. [Core API](/docs/core) documents the package limits and the
server parser requirements.

# AGENTS.md

Rules for writing the documentation site.

- Write for developers evaluating or integrating the editor. Lead with the action, contract, or limitation they need to make a decision.
- Keep one source of truth for each concern. Link to it instead of repeating its explanation on summary, feature, API, and prop pages.
- Describe observable behavior: the input or action and its result. Omit implementation causes, review history, planned fixes, and exhaustive examples unless they change how a developer must use the package.
- Prefer correcting or replacing an existing sentence over adding a new section. Keep the surrounding page concise and ordered by importance.
- Use public names and types in API pages. Use plain product language in feature pages; mention OOXML names only when readers must inspect or produce them.
- Document current limitations that affect data integrity, interoperability, security, or a common workflow. Remove the limitation when the behavior is fixed.
- Avoid absolute claims such as “all,” “every,” and “nothing” unless the documented contract and tests support them.
